# 穗学伴 · 访问日志部署指南

> 目标：用 Cloudflare 免费资源记录**匿名访问统计**，并提供一个**仅管理员可见**的看板。
> 全程 0 元，约 10–15 分钟完成。前端不含任何密码或密钥。

---

## 一、这套方案能做什么 / 不能做什么

**能记录（匿名）：** 访问次数(PV)、匿名访客数(UV)、日期、年级、学科、册次、使用模块、国家/地区、设备类型、浏览器、来源域名。

**不会记录：** IP、姓名、手机号、账号、孩子输入的任何内容、课文原文。访客 ID 经服务端密钥哈希，不可反推、不可跨天追踪。

**重要限制：**
1. 只对**线上版**生效（Pages 站点）。本地双击打开的离线单文件本来就不联网，不会上报。
2. 页面会增加一个到 Worker 的外部请求——这是"记录访问"的必要代价。
3. 匿名统计只能看到"地区/设备/模块分布"，**无法知道访问者是谁**。想识别具体身份需要登录系统，是另一套方案。

## 二、部署步骤

### 第 1 步：创建 D1 数据库并建表

1. 登录 Cloudflare 控制台 → 左侧 **Workers & Pages** → **D1 SQL 数据库** → **Create database**
2. 名称填 `suixue-analytics`，区域默认即可 → 创建
3. 进入该数据库 → **Console** 标签 → 把本目录 `schema.sql` 的全部内容粘贴进去 → 点 **Execute**
4. 看到 `visits` 表和索引创建成功即可

### 第 2 步：创建 Worker 并粘贴代码

1. **Workers & Pages** → **Create** → **Workers** → **Create Worker**
2. 名称填 `suixue-analytics`（或任意，记住生成的域名）
3. 点 **Deploy** 生成默认 Worker，然后点 **Edit code**
4. 把默认代码**全部删除**，粘贴本目录 `worker.js` 的全部内容 → **Deploy**

### 第 3 步：绑定数据库与设置密钥（关键，安全核心）

进入 Worker → **Settings** → **Variables and Secrets**：

| 类型 | 名称 | 值 | 说明 |
|------|------|-----|------|
| Secret | `ADMIN_PASSWORD` | 你自定的管理员密码 | 管理页登录用，只存服务端 |
| Secret | `SESSION_SECRET` | 一长串随机字符 | 会话签名密钥，建议 32 位以上 |
| D1 Database Binding | `DB` | 选 `suixue-analytics` | 在 Variables 页下方 Resources 处添加 |

> `SESSION_SECRET` 可用这个命令生成随机串（在本地终端执行）：
> `node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"`
>
> 绑定 D1 后，Worker 里通过 `env.DB` 访问。改完变量后 Worker 会自动重新部署。

### 第 4 步：验证后端

浏览器打开你的 Worker 域名（如 `https://suixue-analytics.xxx.workers.dev`），应看到管理页登录界面。先随便输个错密码，应提示"密码错误"；这证明密码校验走的是服务端。

### 第 5 步：启用前端上报

打开 `js/analytics.js`，把第 15 行：

```js
var ENDPOINT = '';
```

改成你的 Worker 地址（不要带结尾斜杠）：

```js
var ENDPOINT = 'https://suixue-analytics.xxx.workers.dev';
```

然后在项目根目录重新构建单文件：

```bash
node build.js
```

这会把上报脚本内联进 `穗学伴.html`。再把改动后的 `index.html`、`js/config.js`、`js/analytics.js`、`穗学伴.html` 提交推送到 GitHub Pages 即可上线。

> 若暂时不想启用，保持 `ENDPOINT = ''`，则上报功能完全关闭，页面零外部请求。

## 三、管理员怎么进去（你问的重点）

**入口地址：** 你的 Worker 域名，例如 `https://suixue-analytics.xxx.workers.dev/admin`

安全设计：

1. 管理页本身任何人都能打开，但**只显示一个登录框**；
2. 密码提交到 `/api/login`，在 Worker 服务端与 `ADMIN_PASSWORD` 比对，**前端代码里没有密码**；
3. 校验通过后签发一个 **12 小时有效**的签名 token（HMAC-SHA256），后续接口都要带这个 token；
4. token 只在浏览器内存中，**不落盘、不存 localStorage**，关掉页面即失效；
5. 修改 `ADMIN_PASSWORD` 或 `SESSION_SECRET` 后，所有旧 token 立即作废。

建议：
- 密码设长一点、别和 GitHub 密码相同；
- 不要把 Worker 域名随手发到公开场合（虽然对方看不到数据，但能刷访问量）；
- 想彻底隐藏入口，可给 Worker 自定义域名如 `log.你的域名.com`，不对外宣传即可。

## 四、成本说明

Cloudflare 免费额度：D1 每天 5 万次行写入、10 GB 存储；Workers 每天 10 万次请求。这个学习资料日常访问量远低于此，**实际花费为 0**。若日后访问量极大，免费额度用尽才需付费，届时可加采样率（`analytics.js` 里的 `SAMPLE`）降低成本。
